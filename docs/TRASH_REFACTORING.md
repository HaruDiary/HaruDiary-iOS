# 휴지통 리팩토링

설정 → "최근 삭제한 항목"의 휴지통을 조회·복원·영구 삭제 상태와 보관 정책으로 분리하고,
일기 목록과 같은 카드 형식의 SwiftUI 화면으로 교체했다. 설정 화면은 아직 UIKit이므로
`TrashModule.makeLiveViewController()`로 연결한다. 기존 `TrashVC`는 비교용으로 남기고 경로에서만 뺐다.

## 기존 동작과 바뀐 점

| 기존 (`TrashVC`) | 원인 | 변경 |
|---|---|---|
| 72시간 자동 삭제 코드가 있었지만 호출되지 않아 삭제된 적 없음 | `loadDiaries()` 미호출 | 30일 보관 정책(`DiaryTrashPolicy`)을 휴지통 구독마다 적용 |
| 복원·영구 삭제 결과와 상관없이 완료 처리 | 저장 결과 미확인 | 요청 결과로 완료/실패(성공·실패 개수) 표시 |
| 영구 삭제 시 사진 파일 정리 결과 불명 | 삭제 순서·결과 미기록 | 사진을 먼저 지우고 모두 지워졌을 때만 문서 삭제. 사진 실패 시 일기를 휴지통에 남기고 실패로 표시(재시도 가능) |
| 로그아웃·계정 전환 중 늦은 응답이 화면에 반영될 수 있음 | 사용자 경계 없음 | 구독 중인 사용자에 묶고 세대 값으로 늦은 결과 무시 |
| 목록과 다른 셀·검색 UI | 별도 UIKit 구현 | 목록과 같은 카드 행·검색창·월 헤더 공유 |

## 30일 보관 정책

- 기한: `deleteDate` + 30일. 정책 시작일(2026-09-28 00:00 KST) 이전에 휴지통으로 간 일기는 시작일부터 30일을 센다.
  기존 72시간 코드가 동작하지 않았기 때문에, 첫 실행에서 오래된 휴지통 일기가 한꺼번에 삭제되지 않도록 유예했다.
- 남은 일수는 올림으로 계산한다(1시간 남아도 "1일 남음"). 기한이 지나면 삭제하는 동안 숨기고 자동으로 영구 삭제한다.
  삭제가 실패하면(네트워크·권한 오류) "곧 삭제" 배지로 다시 보여 직접 복원하거나 영구 삭제할 수 있다.
- 자동 삭제는 휴지통 화면이 구독을 받을 때 실행된다. 앱을 열지 않은 기간에는 서버에서 지워지지 않는다(서버 함수 없음).
- 같은 일기의 중복 삭제 요청은 `ExpiredTrashPurger`가 막는다. 사용자가 바뀌거나 화면이 구독을 멈추면 남은 자동 삭제를 취소한다. 로그에는 개수만 남긴다.
- 영구 삭제 전과 문서 삭제 트랜잭션 안에서 저장된 문서를 다시 확인한다. 직접 영구 삭제와 자동 삭제 모두 휴지통 상태이면서
  화면에서 본 `deleteDate`가 그대로일 때만 지운다. 다른 기기에서 복원했거나 복원 후 다시 휴지통에 넣은 일기는 지우지 않는다. 사진 삭제 도중 복원된 경우 문서는 지켜지지만 이미 지운 사진은 돌아오지 않는다.

## 구성

| 파일 | 책임 |
|---|---|
| `Domain/Trash/DiaryTrashPolicy.swift` | 보관 기간·기한·남은 일수 계산 |
| `Domain/Trash/ExpiredTrashPurger.swift` | 기한이 지난 일기 영구 삭제, 진행 중 요청 중복 방지 |
| `Domain/DiaryTrashing.swift` | 휴지통 이동·복원·영구 삭제 인터페이스 |
| `Data/FirebaseDiaryTrash.swift` | 복원은 `isDeleted`·`deleteDate`만 수정, 영구 삭제는 사진 → 문서 순서. 이미 없는 사진은 삭제된 것으로 처리 |
| `Domain/DiaryList/DiaryListIndex.swift` | `DiaryListScope.trash`로 휴지통 일기만 월별 분류·검색 |
| `Features/Trash/TrashViewModel.swift` | 조회 상태·검색·남은 일수·개별/전체 복원·삭제 결과 |
| `Features/Trash/TrashView.swift` | 카드 목록, "N일 남음" 배지, 스와이프·길게 누르기, 확인창 |
| `Features/Trash/TrashHostingController.swift` | 결과 알림과 일기 보기(`WriteDiaryVC`) 연결 |
| `DesignSystem/DiaryListComponents.swift` | 목록·휴지통 공용 검색창·월 헤더·빈 화면·카드 행 스타일 |

## 화면

- 상단: "최근 삭제한 항목", 보관 안내, ⋯ 메뉴(모두 복원 / 비우기). 비어 있으면 메뉴 비활성.
- 행: 목록과 같은 카드. 제목 줄 끝에 "N일 남음" 배지, 3일 이하는 빨간색, 당일은 "곧 삭제".
- 조작: 탭하면 일기 보기, 왼쪽 스와이프·길게 누르기로 복원/영구 삭제. 영구 삭제와 비우기는 확인 후 실행.
- 전체 작업은 검색 결과가 아니라 휴지통 전체에 적용한다.

## 검증

- 로직 테스트 95개 통과: 보관 정책 5개, 만료 삭제 4개, 휴지통 상태 11개, 휴지통 분류 1개 추가.
- 오프라인 harness(가짜 저장소, 정책 시작 +40일 기준)에서 확인: 28·17·3·1일 배지와 색,
  기한 지난 일기 2개 숨김·자동 삭제, 스와이프 복원, 비우기 확인창(개수 표시) 후 빈 화면.
- 사진 삭제가 일부 실패한 뒤 복원하면 먼저 지워진 사진은 돌아오지 않는다. 대신 Storage에 주인 없는 사진이 남지 않는다.
- 확인하지 못한 것: 실제 Firebase 계정에서의 복원·영구 삭제·사진 파일 삭제와 설정 화면 진입.
