# 앱 잠금

설정 › 잠금에서 4자리 앱 암호를 켜고, 추가로 Face ID/Touch ID로 잠금을 풀 수 있다.

## 동작

- 잠금이 켜져 있으면 앱을 처음 열 때와 백그라운드로 갈 때 별도 창(`AppLockPresenter`)으로 잠금 화면을 덮는다.
  잠금을 풀기 전에는 아래 화면을 보거나 누를 수 없고, 앱 전환기에도 잠금 화면이 보인다.
- Face ID/Touch ID를 켰으면 앱이 활성화될 때 한 번 자동으로 묻는다. 실패·취소하면 앱 암호로 푼다.
  이때 iPhone 암호 입력은 제공하지 않는다(앱 암호가 대체 수단).
- 틀린 암호 5번째부터 30초, 1분, 5분, 이후 15분씩 기다린다. 대기는 앱을 다시 켜도 유지되며,
  설정에서 현재 암호를 확인할 때도 같은 횟수에 포함된다.
- 암호를 잊으면 잠금 화면의 "암호를 잊었어요"로 iPhone 암호(또는 Face ID)로 본인을 확인한 뒤 잠금을 끈다.
  일기 데이터는 바뀌지 않는다.
- 암호 끄기·변경은 현재 암호를 먼저 확인한다. Face ID를 켤 때는 한 번 인증해 본다.

## 저장

| 값 | 위치 |
|---|---|
| 암호 | 키체인(이 기기에서만, 백업 제외). 16바이트 솔트 + SHA-256 해시만 저장 |
| Face ID 사용, 틀린 횟수, 대기 종료 시각 | UserDefaults (`AppLock*`) |

앱을 지웠다가 다시 설치하면 UserDefaults가 비므로, 남아 있는 키체인 암호를 지우고 잠금 꺼짐으로 시작한다.

## 기존 사용자

이전 버전의 생체 인식 잠금(`BiometricsEnabled`, 앱 암호 없음)을 켠 사용자는 업데이트 후에도 잠겨 있다.
전과 같이 Face ID 또는 iPhone 암호로 풀면 앱 암호를 정하라고 안내하고, 정하면 Face ID도 켠 새 잠금으로 바뀐다.
이전 버전은 앱을 처음 열 때 잠그지 않았고 인증에 실패해도 앱을 쓸 수 있었는데, 이 두 가지를 막았다.

## 검증

- `AppLockTests`, `LockViewModelTests`: 해시 저장, 대기 시간, 재실행 후 대기 유지, 기존 잠금 전환, 설정·잠금 화면 흐름.
- 시뮬레이터(Face ID 등록): 암호 설정(불일치 재입력 포함), Face ID 켜기, 앱 시작·복귀 잠금, Face ID 실패 후 암호,
  틀린 암호 안내, Face ID로 해제, 암호 분실 후 잠금 끄기, 기존 잠금 사용자 안내를 확인했다.
- 실기기 Face ID/Touch ID는 확인하지 않았다. 기존 `LockVC`, `SetFaceID.swift`는 삭제했다.
