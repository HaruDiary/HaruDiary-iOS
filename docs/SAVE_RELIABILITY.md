# 일기 저장·조회 신뢰성 (P0)

## 사진 저장 실패의 원인: Firebase Storage 요금제

사진 업로드는 `HTTP 402 (FIRStorageErrorDomain -13013)`로 거절된다. 로그에 함께 보이는
`400 "Upload has already been finalized"`는 실패한 업로드를 SDK가 정리하면서 생기는 부수 에러다.

2026년 2월 3일부터 Cloud Storage for Firebase는 Spark(무료) 요금제를 지원하지 않는다.
Spark 프로젝트는 기본 버킷(`*.appspot.com`)을 포함한 모든 Storage에 **읽기·쓰기 권한을 잃고**
402/403을 받는다. 새 사진 업로드와 기존 사진 표시가 모두 영향을 받는다.
해결은 프로젝트를 Blaze(종량제) 요금제로 전환하는 것이며 코드로 해결할 수 없다.
[Firebase FAQ](https://firebase.google.com/docs/storage/faqs-storage-changes-announced-sept-2024)

## 코드에서 고친 것

| 문제 | 수정 |
|---|---|
| 문서 하나의 디코딩 실패가 목록·캘린더 전체 구독을 실패시킴 | `DiaryDocumentDecoding`: 문서별 디코딩, 실패한 문서만 건너뛰고 건수만 로그 |
| 업로드 실패 후에도 `downloadURL`을 요청하고 원인을 남기지 않음 | 실패 시 URL 요청 없이 실패로 처리, 에러 도메인·코드만 로그 |
| 새 일기의 사진 업로드가 실패해도 알림 없이 사진만 빠진 채 저장 | 글은 저장하고 "사진 N장을 저장하지 못했습니다" 알림 표시 |
| 수정 시 기존 사진을 먼저 삭제하고, 업로드 실패 시 사진 참조를 빈 값으로 저장 | `DiaryPhotoReplacement`: 업로드 → 저장 → 이전 파일 삭제. 실패 시 이전 사진 유지, 글 수정만 저장 |
| 익명 로그인 실패 시 완료 신호가 없어 목록의 "저장 중" 표시가 남음 | 실패를 완료로 전달해 표시를 해제하고 "저장 실패" 알림 표시 |
| 실패 알림을 화면에 없는 `DiaryListVC()`에 표시해 보이지 않음 | `TemporaryAlert.presentOnTopScreen`: 현재 맨 위 화면에 표시 |

## 검증

- 단위 테스트: 문서별 디코딩 3개, 사진 교체 순서 5개(성공·업로드 실패·저장 실패·전체 삭제·재사용 URL).
- 실제 앱(로그인 계정, 현재 402 환경): 사진이 포함된 새 일기 → 글 저장 + 사진 실패 알림 표시,
  일기 수정 중 사진 추가 → 글 수정 저장 + 사진 유지 알림 표시를 확인했다.
- 익명 로그인 실패 경로는 운영 Firebase에 계정을 만들 수 있어 실행 검증하지 않았다(코드 확인만).
- Blaze 전환 후의 업로드 성공 경로(업로드 → 저장 → 이전 파일 삭제)는 아직 실행 검증하지 못했다.
