# App Store 2.0 출시 준비

App Store Connect에 2.0 버전을 제출할 때 쓰는 문구와 확인 항목이다. 개인정보 라벨은 2026-10-13 `dev`의 코드 기준이다.
코드가 저장하는 데이터가 바뀌면 이 문서와 라벨, 개인정보 처리방침을 함께 고친다.

## 순서

1. `dev` 최신 커밋으로 Xcode Cloud 빌드를 만든다([XCODE_CLOUD.md](XCODE_CLOUD.md)). TestFlight 빌드 번호가 겹치지 않는지 본다.
2. TestFlight로 실기기에서 로그인(Apple·Google·손님), 일기 쓰기·사진, 위젯, 회원 탈퇴, 여정 탭을 확인한다.
3. App Store Connect › 앱 › iOS 앱 옆 `+` › 버전 `2.0`을 만들고 아래 문구·스크린샷·빌드를 넣는다.
4. 앱 개인정보 라벨, 연령 등급 설문, 개인정보 처리방침을 아래 기준으로 갱신한다.
5. 심사 메모를 넣고 "심사에 제출"한다. 출시는 수동 또는 단계적 출시를 고른다.

## 이번 버전의 새로운 기능

```text
하루일기가 새로워졌어요.

• 여정: 일기를 쓴 날만큼 채워지는 열두 달의 그림, 한 해 동안 자라나는 나만의 도시
• 홈 화면 위젯: 오늘 일기를 썼는지, 이번 달 기록과 오늘의 글귀
• 다크 모드와 화면 모드 설정
• 쓰던 글 보관: 앱을 닫아도 쓰던 일기가 남아요
• 작년 오늘의 일기, 기분 통계, 글감 질문
• 일기 내보내기
• 캘린더 공휴일 표시와 밀어서 달 넘기기
• 화면 전체를 새로 만들어 더 빠르고 부드러워졌어요
```

## 스크린샷

- iPhone 전용 앱(`TARGETED_DEVICE_FAMILY = 1`)이라 6.9인치 iPhone 스크린샷만 있으면 된다(1320×2868 또는 1290×2796).
- 실제 사용자 일기가 보이지 않게 한다. 운영 Firebase에 예시 일기를 쓰지 않는다.

## 앱 개인정보 라벨

추적: 없음(광고·분석 SDK 없음. 사용하는 SDK는 Firebase Auth·Firestore·Storage, Google Sign-In).
아래 항목은 모두 "앱 기능" 용도이고 사용자와 연결된다.

| 분류 | 항목 | 근거 |
|---|---|---|
| 연락처 정보 | 이메일 주소 | 로그인 계정, `users/{UID}`의 `email` |
| 연락처 정보 | 이름 | 닉네임(`nickname`, Firebase 프로필 이름) |
| 식별자 | 사용자 ID | Firebase UID, 문의용 코드 |
| 사용자 콘텐츠 | 사진 또는 비디오 | 일기 사진, 프로필 사진(Firebase Storage) |
| 사용자 콘텐츠 | 기타 사용자 콘텐츠 | 일기 제목·내용·기분·날씨 |

- 위치는 수집하지 않는다. 날씨는 기기 위치로 Apple WeatherKit에서 받아 오고, 사진의 장소는 기기 안에서만 읽는다.
  서버에는 사진의 iCloud 사진 식별자만 저장한다([DIARY_WRITING_REFACTORING.md](DIARY_WRITING_REFACTORING.md)의 "위치").
- 2.0 이전에 저장된 일기·사진에는 위치가 남아 있다. 지우려면 운영 데이터 변경 승인이 필요하다.

## 연령 등급

- 일기는 본인만 보고 다른 사용자와 공유·노출하는 기능이 없다. 새 설문(소셜 미디어·사용자 생성 콘텐츠)도 이 기준으로 답한다.

## 심사 메모

```text
로그인하지 않고 일기를 저장하면 익명(손님) 계정으로 저장되어 바로 사용해 볼 수 있습니다.
Apple 또는 Google 계정으로 로그인하면 기기 간에 일기가 동기화됩니다.
회원 탈퇴: 설정 › 회원 탈퇴 (일기·사진·계정이 삭제됩니다).
여정 탭은 일기를 쓴 날짜 수로 그림이 채워집니다.
```

## 이미 갖춘 것

- 계정 삭제 기능, Google 로그인과 함께 제공하는 Apple 로그인
- 암호화 수출 규정: `ITSAppUsesNonExemptEncryption = NO`
- 권한 문구: 사진, 위치(날씨), Face ID
