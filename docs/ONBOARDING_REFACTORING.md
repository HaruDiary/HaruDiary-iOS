# 5페이지 온보딩

## 사용자 흐름

사용자 요청에 따라 `docs/design/redesign-v2/05-onboarding.png`의 5페이지 순서와 문구를 적용했다.
라벤더 색상, 상단 브랜드·건너뛰기, 중앙 그림·설명, 하단 원형 진행 표시 5개·버튼으로 구성한다.

| 페이지 | 제목 | 설명 |
|---|---|---|
| 기록 | 오늘의 일기를 기록해보아요 | 글과 사진으로 하루를 남겨요 |
| 불빛 | 일기를 작성하고 불을 밝히세요 | 기록한 하루가 작은 불빛이 돼요 |
| 여정 | 일기를 채우고 건물을 세우세요 | 한 달의 기록이 나만의 풍경으로 |
| 캘린더 | 캘린더로 기록한 일기를 확인해요 | 다시 보고 싶은 날을 찾아보세요 |
| 보관 | 일기를 안전하게 저장하세요 | 소중한 이야기를 오래 간직하세요 |

1~4페이지는 ‘다음’, 5페이지는 ‘시작하기’를 표시한다.
불빛·여정은 이번 요청에 따른 목업 소개 문구와 이미지다. 실제 마을 보상 규칙이나 새 저장 스키마는 구현하지 않았다.
새 목업의 중앙 그림 5장을 그대로 사용한다. 추출 위치와 자산 경로는 [목업 이미지 기록](design/ONBOARDING_ILLUSTRATIONS.md)에 있다.

## 책임

- `OnboardingProgressStore`: 기존 `hasSeenOnboarding` 키를 읽고 쓰는 최소 계약.
- `OnboardingViewModel`: 페이지 선택·이동·건너뛰기·완료. Foundation/Observation에만 의존한다.
- `OnboardingView`: 그림·설명·버튼·스와이프·접근성 표시. Firebase에 접근하지 않는다.
- `OnboardingModule`: UIWindow와 SwiftUI를 연결하고 완료 후 기존 메인 탭을 생성한다.
- `SceneDelegate`: 최초 진입에 Module을 호출한다. 앱 전체 탭·탐색을 다시 구성하지 않는다.

기존 UIKit `StartVC`에도 progress store를 연결하고 완료 시 로그아웃을 제거했다.
`StartVC`, `PageVC`, `ContentVC`와 이전 자산은 통합 비교용으로 남겨 뒀으며 현재 앱 진입에서는 사용하지 않는다.
새 온보딩 자체는 SnapKit을 사용하지 않는다.

## 보존과 변경

- 기존 완료 사용자는 새 5페이지 온보딩을 다시 보지 않는다.
- 중간에 앱을 종료하면 완료로 기록하지 않으며 다음 실행은 첫 페이지에서 시작한다.
- 건너뛰기와 마지막 시작 버튼은 완료를 저장하고 메인 화면으로 이동한다.
- 완료 후 늦은 페이지 이벤트와 중복 완료를 무시한다.
- 온보딩 완료는 기존 로그인·익명 계정을 변경하지 않는다. 기존 로그아웃 동작은 제거했다.
- 첫 실행에는 메인 탭을 미리 생성하지 않아 화면 노출과 불필요한 구독 시작을 피한다.
- AppDelegate의 즉시 위치 권한 요청을 제거했다. 기존 WeatherService/MapManager의 사용 시점 요청은 유지한다.
- 자동 로그인·설정 변경·운영 데이터 변경을 수행하지 않는다.

## 모션·접근성

- SwiftUI HStack에 5페이지를 고정하고 선택 인덱스에 따라 가로 offset을 약 0.32초 ease-in-out으로 이동한다. 스와이프·다음·페이지 표시 버튼은 같은 선택 상태를 사용한다. `TabView`의 프로그램 선택 변경에서 애니메이션 없이 화면이 교체되는 문제를 재현한 뒤 교체했다.
- 페이지 표시의 색상은 약 0.2초, 버튼 눌림은 약 0.15초로 반응한다.
- 반복 부유·반짝임 효과 없이 그림 디테일과 직접 조작에 집중한다.
- 다음/페이지 버튼은 애니메이션 완료 콜백까지 추가 탭을 막는다. 고정 시간 대기 작업은 사용하지 않는다.
- 가로 드래그는 손가락 이동량을 반영하고 놓으면 다음/이전 페이지에 정렬된다. 첫/마지막 경계를 넘지 않으며 마지막 페이지 스와이프는 온보딩을 완료하지 않는다.
- 메인으로 넘어갈 때는 짧은 cross-dissolve를 사용한다.
- 시스템 동작 줄이기는 프로그램에 의한 페이지 애니메이션·버튼 확대축소·메인 전환에 반영한다.
- 그림은 장식으로 처리하고 페이지·버튼에는 접근성 설명을 제공한다.
- 글자는 Dynamic Type을 따르며 중앙 내용은 필요할 때 세로 스크롤된다. 하단 버튼은 고정한다.

## 검증

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer bash scripts/ci.sh test
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer bash scripts/ci.sh build
```

- 변경 전 기존 27개 테스트 통과.
- 신규 9개(첫 실행·전체 진행·역방향 이동·건너뛰기·중복 완료·기존 완료·중단·재실행·기존 키 호환)와 기존 27개: 총 36개 통과.
- 가로 전환·목업 이미지 수정 후 위 test 명령으로 총 36개 통과. 앱 build 명령은 `HARUDIARY_CI_OUTPUT=/tmp/harudiary-onboarding-motion-build`를 지정해 통과했다.
- 별도 오프라인 UIKit harness에서 실제 기존 StartVC/PageVC/ContentVC와 fake 인증 경계를 사용했다. 완료 후 기존 사용자가 사라지는 실패를 재현했고 수정 후 기존 사용자 유지·완료 저장을 확인했다.
- SwiftUI 온보딩 소스와 자산을 그대로 사용하는 별도 오프라인 검증 앱을 컴파일·실행했다. 메인 탭과 인증만 stub이며 운영 Firebase에는 연결하지 않는다.
- 5페이지 변경 전 전체 진행 테스트를 먼저 수정해 기존 3페이지 구현의 실패를 확인했다. 변경 후 총 36개 테스트가 통과했다.
- 오프라인 검증 앱에서 5페이지 이미지·문구, 다음 버튼 순차 이동, 마지막 시작 버튼, 페이지 표시로 역방향 이동을 확인했다. 시작·건너뛰기의 완료 저장, fake 계정 보존, 메인 1회 생성, 재실행 시 온보딩 생략도 확인했다.
- 접근성 최대 글자 크기에서 첫 페이지의 제목·설명·하단 버튼을 확인했다. 모든 페이지와 작은 기기 조합을 검증한 것은 아니다.
- 전환 수정 전 녹화에서 내용이 곧바로 교체되는 현상을 확인했다. 수정 후 녹화의 중간 프레임에서 이전/다음 페이지가 동시에 보이며 가로로 이동하는 것을 확인했다.
- 수정 후 시뮬레이터에서 좌우 드래그로 다음/이전 페이지 이동, 첫/마지막 경계, 완료 처리를 확인했다. 큰 글자 설정의 기록·캘린더 페이지에서도 세로 드래그가 가로 페이지를 변경하지 않음을 확인했다. 실제 Firebase 세션, 위치 권한 요청 시점, 실기기의 프레임 안정성은 별도 확인이 필요하다.

## 협업 시 확인

온보딩 변경 파일은 Features/Onboarding, Domain/Onboarding, 목업 이미지 자산이다.
공통 변경은 DiaryTheme, 프로젝트 타깃 연결, SceneDelegate의 진입 분기와 AppDelegate의 위치 권한 요청 제거에 한정한다.
앱 전체 세션·탐색 전환 시 `OnboardingModule`의 UIKit 연결을 제거할 수 있다.
